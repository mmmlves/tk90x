# TK95 vs TK90X: ROMs, hardware, and choosing a default machine

Research date: 2026-10-14. Every byte-level claim below was checked locally against the ROM files.
Where a statement comes from a secondary source or is my own inference, it says so.

## 0. TL;DR

- `roms/tk95.rom` (CRC32 `17368e07`, SHA1 `94edc401d43b0e9a9cdc1d35de4b6462dc414ab3`) is
  byte-identical to the MAME `tk95` dump. EightyOne ships the same file, under both of its names
  (`tk90.rom` and `tk95.rom`). The code matches the Cantinho do TK90X blog's description of the
  TK95 ROM. Treat it as the genuine Portuguese TK95 ROM.
- `roms/tk90x.rom` (CRC32 `3e785f6f`) is byte-identical to the MAME `tk90x` dump. However, it is
  **not the original 1985 TK90X ROM**. It is the second-generation code, the same code as the TK95,
  with only the boot banner changed (20 bytes at 0x3AAE-0x3AC3). The original 1985 TK90X ROM
  (9128B mask ROM) is the file that ZEsarUX calls `tk90xs.rom` (CRC32 `d1b2f352`).
- Hardware: the TK95 uses the same TK90X motherboard and the same Microdigital ULA. It has a new
  case (Commodore Plus/4 style) and a 57-key "semi-professional" keyboard with Spectrum+ style keys.
  Diode D1 is removed at the factory, which changes bit 7 of port 0xFE. Video is still **60 Hz
  PAL-M** by default.
- For a games-first emulator, the TK95 ROM is the best *TK* ROM. However, no TK model should be the
  default at **60 Hz**, and none is a substitute for a real 48K ROM. See section 3.

## 1. ROM identity and versions

### 1.1 MAME

`src/mame/sinclair/spectrum.cpp` (last commit touching the file: `774a180d`, 2026-07-24):

```
ROM_START(tk90x)
	ROM_LOAD("tk90x.rom",0x0000,0x4000, CRC(3e785f6f) SHA1(9a943a008be13194fb006bddffa7d22d2277813f))
ROM_START(tk95)
	ROM_LOAD("tk95.rom",0x0000,0x4000, CRC(17368e07) SHA1(94edc401d43b0e9a9cdc1d35de4b6462dc414ab3))
COMP( 1985, tk90x, spectrum, 0, spectrum_clone, spectrum,  ..., "Micro Digital", "TK 90X Color Computer", 0 )
COMP( 1986, tk95,  spectrum, 0, spectrum_clone, spec_plus, ..., "Micro Digital", "TK 95 Color Computer",  0 )
```

- MAME lists exactly one ROM per machine and has no alternate BIOS sets.
- Both machines use `spectrum_clone`, which is the plain 48K `spectrum` config (50 Hz Sinclair
  timing) with "no floating bus" (port reads return 0xFF). The only difference MAME models between
  the TK90X and the TK95 is the keyboard input layout (`spectrum` vs `spec_plus`).
- MAME note 15 says: "The TK90X and TK95 roms output 0 to port #df on start up ... not emulated".
  This matches the ROM: at 0x0013 there is `XOR A; OUT (0xDF),A; RET`.

Both project ROMs match MAME exactly (CRC32 and SHA1 recomputed locally).

Differences between files (byte counts, measured locally):

- `tk90x`(MAME) vs `tk95`: 20 bytes, banner only.
- Original v1 (`tk90xs`) vs `tk95`: 875 bytes, mostly in these places:
  - the error-message table at 0x1392-0x1543;
  - the area at 0x386E-0x3A29;
  - 0x04B9/0x04BB, 0x0C46 and the banner.
- Either TK ROM vs the Sinclair 48K ROM (`48.rom`, ddee531f): about 1980 bytes in 71 ranges.

**Are there multiple TK95 ROM versions?** Yes. There are at least two factory variants of the same
code: Portuguese (`17368e07`) and Spanish/export (`602ba2c9`). They differ in one byte. Wikipedia
(en) also says that some users installed switchable ROMs, so modified images also circulate.

**Caveat on MAME's `tk90x`.** In 2015 the blog author found that his own "TK90X ROM" image "na
verdade não era original, mas do TK95 com modificação na tela inicial" ("was not actually the
original, but the TK95 one with the boot screen modified"). There are two possible explanations for
MAME's `3e785f6f`:

- it is the same kind of rebannered TK95 image; or
- it is a genuine late-production Portuguese TK90X v2 ROM. A Spanish v2 TK90X ROM demonstrably
  exists (Leonardo's Uruguayan TK90X).

No source settles this. Either way, it is **not** the 1985 v1 ROM, and it behaves exactly like the
TK95 ROM.

### 1.3 Why the TK95-generation ROM is more compatible (verified)

The blog tested 120 AY demos. With the v1 TK90X ROM, about 20% of them were unusable, all because
of IM2 interrupt handling. With the TK95 ROM only 1 failed (0.8%), and that one was the Misha
Megademo, which failed because of the UDG token.

I checked the ROMs directly. With IM 2 and the usual 0xFF on the data bus, the vector is read from
`I*256+0xFF`:

- Sinclair 48K: I=0x38..0x3B gives vector 0xFFFF. Many games rely on this.
- `tk95.rom` and `tk90x.rom` (MAME): I=0x38..0x3B also gives 0xFFFF, so the behaviour is preserved.
- Original v1 `tk90xs.rom`: these I values give 0x656A, 0x7320, 0xFD3A and 0x11F1, so the program
  crashes.

This probably also explains the Wikipedia claim that "Mikie runs only on the TK95, not on the
TK90X". That last link is my inference.

Incompatibilities that remain in **all** TK ROMs:

- Token codes 0 = `UDG` and 1 = `TRACE` are executed by the BASIC interpreter, not ignored. BASIC
  loaders with embedded control codes `16 32 0` break.
- `RST 18h` (GET-CHAR) detours through 0x3CFB (`CP 2; CCF; JP 0025h`). That address is inside the
  Beta 48 DOS paged window at 0x3C00-0x3CFF, so the CAS/Beta interfaces hang unless their ROM is
  patched.
- Messages are relocated and translated. Software that checksums the ROM or jumps into ROM
  internals may fail.

## 2. Hardware: TK95 vs TK90X

| Aspect | TK90X (1985) | TK95 (1986) | Source |
|---|---|---|---|
| Board / ULA | Microdigital CMOS ULA clone ("MC16845"), with the analog parts outside the chip | **Same board** (silkscreen still says TK90X) and same ULA. Only a resistor and an LED were added. | en.wiki TK90X; Cantinho 2013-02-12 |
| CPU | Z80A at 3.575611 MHz (PAL-M colour subcarrier) | same. The en.wiki TK95 infobox says "Z80B 3.5 MHz", but its own text says Z80A 3.58 MHz. | Cantinho 2013-04-09; pt.wiki |
| RAM | 16 KB or 48 KB versions; 4116 + 4416 DRAM (a 1989 board used 4464) | 48 KB | en.wiki; Cantinho 2015-07-25 |
| Case / keyboard | Spectrum-like rubber keys; UDG on the £ key, ç/ñ/accents, TRACE | Plus/4-style case; 57 "semi-professional" keys with springs; Spectrum+ style keys including Extend Mode | pt.wiki TK95; Cantinho 2013-02-12; MAME `spec_plus` |
| Port FE bit 7 (read) | 0, because diode D1 ties it to ULA pin 10 (and selects Portuguese on the v1 ROM) | D1 removed at the factory, so the bit floats: usually 1, but it picks up ULA attribute fetches when FLASH=0 | Cantinho 2012-04-21 and 2012-11-13 |
| Port FE bit 6 (EAR) | Idles at **1** (transistor amplifier; Issue 3 Spectrum gives 0) | same | Cantinho 2012-04-21 |
| Port FE bit 5 | Not connected; reflects the last attribute byte the ULA fetched (PAPER bit 2) | same | Cantinho 2012-04-21 |
| Joystick | Built-in DB9, Interface 2 / Sinclair 1 (keys 6-0); a non-standard pin enables Sinclair 2 (1-5) | DB9 "Atari standard" (pt.wiki), same board, so presumably the same Sinclair mapping (zxsp also models it as Sinclair) | Cantinho 2013-08-14; pt.wiki; zxsp |
| Video, default | **60 Hz PAL-M**: 228 T/line × 262 lines = **59 736 T/frame** (59.857 Hz). 15 top border + 192 display + 22 bottom border lines. Each line is 24T left border + 128T display + 24T right border + 52T retrace. | same board and ULA. Nobody has published separate TK95 measurements. | Cantinho 2013-03-25 and 2013-04-09 (measured with minfo/fusetest/Videotime 2) |
| Video, 50 Hz | Grounding ULA pin 1 gives 228 T × 312 lines = **71 136 T** (50.264 Hz). Export (Uruguay/Argentina) units were wired for PAL-N 50 Hz. | Same mod, done on a TK95 in 2015 | Cantinho 2013-03-17, 2013-03-27 and 2015-07-07; en.wiki |
| Contention | Undocumented. Test programs gave implausible results. | same | Cantinho 2012-05-19 |
| Sound | Beeper, also routed to the TV RF output | same | en.wiki |

Differences from a Sinclair 48K (69 888 T = 224 × 312, 3.5 MHz):

- Lines are 228 T, not 224, and the clock is 3.5756 MHz.
- At 60 Hz the frame is 262 lines.

This breaks raster and multicolour effects, for example in Rotatrix and Bifrost. The blog found that
60 Hz affects 9.2% of demos. Among games it affects music and game speed (+20%), and Comando Tracer
crashes outright.

Emulator note: the zxsp TK model uses 224 T × 264 lines = 59 136 T at 3.58 MHz. That figure was
copied from the Chilean NTSC Spectrum and contradicts the real TK90X measurement of 228 × 262. MAME
and ZEsarUX emulate the TKs with plain 48K 50 Hz timing.

## 3. Should the TK95 be the default machine of a 48K-games emulator?

Reasons for: among TK ROMs, the TK95 ROM is clearly the most compatible. It fixes the IM2 0xFFFF
table, which affected about 20% of the AY demos tested. MAME's `tk90x` ROM has the same code, so it
behaves the same.

Reasons against making the TK95 the default:

1. **60 Hz timing.** It is authentic, but Spectrum games are written for 50 Hz and 69 888 T. At 60 Hz
   games run about 20% faster (music too), and raster, border and multicolour effects break. Some
   titles crash (Comando Tracer; demos such as Higher State and Megalomania). If the TK95 is the
   default, the emulator should default to the TK 50 Hz mode (71 136 T) or offer a switch. Real
   owners installed that switch for exactly this reason.
2. **It is not a 48K ROM.** The UDG/TRACE tokens, the RST 18h detour at 0x3CFB (which conflicts with
   Beta 48 / TR-DOS paging) and the relocated messages remain. Any ROM-checksum or ROM-internal
   dependency breaks. The authentic period fix was a TK/ZX ROM switch, so the emulator should offer
   the Sinclair 48K ROM.
3. **Port FE quirks.** EAR bit 6 idles at 1 (Samurai Warrior hangs; OTLA turbo loaders fail), and
   bits 5 and 7 float with attribute data. Software that tests the whole byte misbehaves.
4. **Uncertain emulation fidelity.** Contention is undocumented and no TK95-specific measurements
   exist. A TK default therefore cannot be cycle-exact, whereas a 48K default can.

Recommendation (my opinion):

- For a TK-branded emulator, use the TK95 ROM as the default TK ROM, but boot at 50 Hz, or make
  50/60 Hz a prominent toggle.
- Ship a "ZX Spectrum 48K (Sinclair ROM, 69 888 T)" profile for maximum game compatibility.
- Keep the 60 Hz TK90X/TK95 timing (228 × 262) as an authenticity option.
